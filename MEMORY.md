# Project Research Memory

Persistent, project-scoped memory for ResearchForge. It lives in PostgreSQL (migration `0006`), belongs to a **project** (never to a user), and is
shown in the Research Workspace under "Project research memory". Nothing here is generated by an LLM.

## 1. Audit of Phase 1 (state before this work)

| Area | Finding |
|---|---|
| Literature retrieval | 7 providers, merged and ranked, identifier verification. Preserved unchanged. |
| Metadata extraction | `extraction.py` is deterministic keyword matching on title/abstract/keywords for modality, disease, dataset and method, each with matched text and field. **No** research objective, sample size, population, preprocessing, feature extraction, training/validation strategy, metrics, results, limitations or future work. No timestamp, confidence, section or page. Abstract only, never full text. |
| Citation tracking | `reference_ids` (OpenAlex only) and `cited_by_count`. Paper-to-paper links exist only between saved OpenAlex papers. No full reference lists, no incoming links, no citation contexts. A citation is connectivity, not support. |
| Evidence tracking | Did not exist: no claims, supporting/contradicting evidence, passages, section/page provenance or quality rating. |
| Knowledge graph | `frontend/src/lib/graph.ts` builds the graph in the browser from saved projects/papers. Edges are not persisted and carry no provenance field; tag edges embed the matched text in their label. Synthetic sample data is a separate builder (`buildSampleGraph`) and is not mixed into the real graph. Unchanged by this work. |
| Project memory | **No memory engine existed**, only the Project record and the reading list. |

## 2. Schema (migration 0006, additive only)

`project_memories` (one per project) · `memory_entries` (unique `(project_id, content_hash)`) · `research_claims` · `claim_evidence` ·
`research_decisions` (append-only, `supersedes_id`) · `research_gaps` · `memory_events` (audit log). Every table cascades from `projects`;
paper metadata is referenced via `paper_id`, never copied. CHECK constraints pin every status/type vocabulary.

## 3. How entries are made and what they mean

| `source_type` | Meaning | Starts as |
|---|---|---|
| `source_metadata` | Value the provider returned (type, venue, year) | `source_reported` |
| `rule_extracted` | Regex/keyword match on the paper's title/abstract. Keeps the matched sentence, section, method and time. **No confidence is invented** (`confidence` is NULL) | `unverified` |
| `researcher_entered` | Typed by the researcher, or the project record itself | `confirmed` |
| `researcher_confirmed` | A rule/auto entry the researcher confirmed or edited | `confirmed` / `edited` |
| `ai_extracted` | Reserved for a future provider-independent interface. Nothing writes it today | — |

Numeric extractors (`extract_sample_sizes`, `extract_reported_metrics`) match only explicit statements such as `n = 245`, `1,245 participants`,
`accuracy of 92.3%`, and return the whole sentence so a number keeps its dataset/validation context. Fields with no extractor
(objective, population, preprocessing, feature extraction, training/validation strategy, findings, limitations, future research)
stay **missing** until a researcher adds them; the Overview lists them.

## 4. Idempotency, review and conflicts

* `content_hash = sha256(origin|type|paper|field|normalised content)`, unique per project: reprocessing a paper or rebuilding never duplicates.
* A rebuild inserts missing entries and removes only **unreviewed automatic** entries that are no longer produced (e.g. after a project edit
  or a paper removal). Confirmed, edited or rejected entries are never overwritten, deleted or re-created. Editing keeps the original hash and provenance.
* Saving a paper updates memory afterwards, in its own transaction. A memory failure is logged and never undoes the saved paper.
* Conflicts are surfaced, never resolved: a claim with both `supports` and `contradicts` evidence is flagged *contested*; the same metric reported
  with different values by different papers is listed as `metric_variation` with each paper's sentence and named datasets, plus a "not directly comparable" note.
* Evidence quotes are checked against the stored title/abstract: `source_matched` only when the text literally occurs, otherwise `unverified`.
  Full text is not stored, so a quote from the body can never show as verified.
* A claim must have at least one evidence item **or** be marked `hypothesis`. A decision is never edited in place: replacing one creates a new row and marks the old
  one `superseded`. Gaps always start `potential` and carry a "not proof of novelty" notice.

## 5. API (all under `/api/projects/{project_id}/memory`, owner-scoped: other users get 404)

`GET ""` overview · `POST ""` researcher entry · `GET /entries` (filters, `limit`/`offset`) · `PATCH /entries/{id}` confirm/reject/edit ·
`GET|POST /claims` · `POST /claims/{id}/evidence` · `PATCH /claims/{id}` · `GET|POST /gaps` · `PATCH /gaps/{id}` · `GET|POST /decisions` ·
`PATCH /decisions/{id}` · `POST /rebuild` · `GET /audit` · `GET /graph` (provenance-tagged edges: `source_verified`, `rule_extracted`,
`researcher_confirmed`, `researcher_entered`; the 3D view does not draw them yet). Writes are rate-limited; a project holds at most 5000 entries.

## 6. Known limitations

* Abstract-level only: no full text, so no section/page provenance beyond `title`/`abstract`/`keywords`.
* Rule extraction misses unusual wording and can mis-match; every item shows its source sentence for that reason.
* Metrics are matched by name and number only; a value is not tied to a dataset except through the sentence and the datasets named in the same paper.
* No AI extraction yet; `ai_extracted` and `confidence` are reserved.
* Gap suggestions are not generated automatically (Phase 2). Experiment context stores researcher notes only (Phase 3).
* The existing 3D Knowledge Graph is unchanged; `/memory/graph` is the data contract for a later integration.
* Phase 2 can read claims, evidence, contested findings, gaps and decisions from these tables; Phase 3 can read the `experiment_context` entries. Neither exists yet.

## 7. Deploy

Render already runs `alembic upgrade head` before `uvicorn` (see `render.yaml`), so migration `0006` is applied before the new API serves. Locally:
`cd backend && alembic upgrade head && python -m pytest`, `cd frontend && npm test && npm run build`.
